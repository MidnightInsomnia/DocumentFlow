## Границы результата

- Полный OCR сканов через Tesseract здесь **не проверен**; движок с rus+eng требуется установить отдельно. DOCX/реальные модели и TIFF-preview проверены.
- Проверена чистая и повторно запускаемая disposable БД, не миграция чужой production-БД. Перед переносом нужна резервная копия.
- Маленькая локальная модель 0.5B способна ошибаться; AI не заменяет сверку оригинала и не подтверждает реквизиты сам.
- Строгая permissive-only проверка всех PDF/GPU/toolchain native-бинарников не завершена: детали в `../THIRD_PARTY_NOTICES.md`.
- Проверочные серверы запускались и останавливались внутри foreground-команд. После проверки сервисы **не оставлены работать**. Для пользовательского запуска — `Start-DocumentFlow.cmd` и `README-LOCAL.md`.

## Единственное ревью и закрытие замечаний

`final-code-review.json` — подлинное независимое заключение **passed=false**, оно не переписано после исправлений. Родитель сверил SHA-256 отчёта, HEAD, staged tree/index и все 301 source fingerprint до изменения кода. Все шесть находок перепроверены и исправлены в одном post-review проходе. Второе независимое ревью не запускалось.

`post-review-live.json`: **25 успешных целевых проверок** уже исправленного кода. Они подтверждают:

- DF-L01: конфликтующая аварийная копия переживает два reload, новое редактирование и настоящее заполнение sessionStorage до квоты; исходный TTL не продлевается.
- DF-L02: настоящий API-CAS самого черновика и две реальные вкладки; 409 не стирает вариант победителя и локальный ввод проигравшей вкладки; повторное сохранение из первой вкладки работает.
- DF-L03: последовательный обход трёх документов без A/B/A/B; поисковая очередь достигает 21-го документа за первой страницей и не подтверждает пропущенные документы.
- DF-L04: новый автоматически завершённый счёт имеет технический маршрут Accounting, но background не назначает ему отключённые справочники; startup-backfill также их не назначает. Старые назначения переживают деактивацию и перезапуск.
- DF-L05: настоящее 15-секундное фоновое чтение не сбрасывает выбранные вид/отдел; явное сохранение записывает именно этот выбор.
- DF-L06: null из запроса становится пустой строкой, остальные поля восстановлены официальным UI.
- Повторно получены реальные semantic результаты и AI-черновик вида; административное подтверждение вида не завершает документ.

После исправлений успешно повторены полный solution build (0 ошибок/предупреждений), frontend build и полный npm audit (0 найденных уязвимостей). Окончательный маленький guard квоты затронул только frontend; после него повторены frontend build/audit и живой сценарий реальной квоты.

`post-review-live-initial.json` и `post-review-live-target-initial.json` сохраняют промежуточные результаты без подмены отказов успехом. Два assertion были неверны в проверочном setup: от документа NeedsReview ожидали уже назначенную бухгалтерию, а integer enum PostgreSQL сравнивали со строковым именем. Это сверено с pipeline, EF-конфигурацией и настоящим журналом Worker. Оставшееся покрытие выполнено целевым продолжением: для истории отдел назначен явно, для новых документов Worker действительно выполнил полный pipeline, состояние до backfill прочитано через PostgreSQL до запуска API.

Родительская квитанция `post-review-closure.json` отделяет фактическое закрытие замечаний от исходного независимого FAIL. Два неблокирующих предложения ревью (просмотр прошлых реквизитов в UI и общий guard админ-форм) оставлены дальнейшими улучшениями. Отчёт ревьюера не выдаётся за повторное одобрение исправленного состояния.
