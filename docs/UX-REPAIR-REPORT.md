# UX и надёжность DocumentFlow: отчёт об исправлениях

## Область

Целевая версия — `ddd/DocumentFlow-Stitch`, ветка `redesign/stitch-sovereign`, исходный HEAD `5432980`. План записан до правок в `.hermes/plans/documentflow-ux-repair.md`. Исходная ветка `master`, архив handoff, рабочие документы и рабочая база не редактировались. Корневой `ddd/Start-DocumentFlow.cmd` не переключался на новую ветку.

## Оценка UX и оформления

Это экспертная оценка двух пользовательских скриншотов, исходников и затем реальных авторизованных экранов, не пользовательское исследование и не полная сертификация доступности.

**Основа удачная:** строгая рабочая тема, оригинал рядом с формой, предметная навигация, читаемые таблицы и разделение автоматического результата и подтверждения человеком. Полная смена дизайна не нужна.

**Основные дефекты были функциональными, а не декоративными:** колесо попадало в scroll-тупик; роль повторялась тремя элементами; неизвестный вид требовал ухода в другой раздел; одинаковая внешняя ошибка скрывала отсутствие OCR; важные подписи не помещались в ограничения ширины. Они делали интерфейс менее аккуратным и менее предсказуемым одновременно.

**Визуальное решение:** сохранить Stitch Sovereign и существующую типографику, убрать дублирование, исправить внутренние отступы, позволить навигации занимать реальную ширину и раньше переносить её на отдельную строку. Не добавлялись декоративные метрики, новые карточные сетки или новая палитра. После просмотра реальных экранов отдельно убрана растянутая на всю ширину кнопка создания пользователя.

## Что исправлено

### 1. Прокрутка справа от документа

Причина — `overscroll-behavior: contain` на обеих колонках обычной карточки. При отсутствии переполнения справа или достижении края событие не переходило к странице.

В обычной карточке включена естественная передача прокрутки родителю. В cinema сохранены отдельные ограниченные viewport-колонки. Реальное колесо мыши над правой колонкой переместило страницу с `scrollY=402` до `630`; проверены открытие cinema, доступ к правой форме, выход и восстановление body overflow.

### 2. Роли и отступы

- В строке пользователя только один dropdown роли с доступным названием; повторный badge и видимая подпись «Роль admin» удалены. Подтверждение понижения и существующие серверные ограничения не убирались.
- У «Администрирования» убран конфликтующий `max-width:140px`, запрещено сжатие текста, сохранены боковые отступы; на промежуточной ширине навигация переносится раньше.
- Статусы каталога больше не используют `display:table`; у них `inline-flex` и явный padding. Полные подписи не заменялись ellipsis.

### 3. Единая загрузка и глобальный drop

**Отдельная кнопка «Пакетная загрузка» нецелесообразна:** это тот же приём файлов с другим количеством. Теперь действие называется «Загрузить документы»; пакетная обработка, лимиты и пофайловые результаты сохранены.

- При file drag над авторизованным приложением появляется полноэкранная область, в том числе поверх cinema. Текст/ссылки не считаются файлами.
- Один capture-owner исключает двойное добавление из локальной и глобальной зон; drop всегда добавляет в список, не заменяет его.
- `File` хранятся только в памяти вкладки, не сериализуются в router state/sessionStorage. Отмена ухода с несохранённой формы сохраняет и форму, и перетащенные файлы; отдельный banner позволяет открыть список позже.
- Отправка начинается только по кнопке. Во время текущей отправки следующий drop ожидает завершения партии. Смена сеанса очищает ожидающие файлы.
- Проверен переход из admin Layout в загрузку и последующее добавление без дублей. Реальная партия дала один принятый документ и два серверных бинарных дубликата.

### 4. Почему не работал Tesseract

В текущем окружении нет доступного `tesseract.exe`: PATH не разрешает команду, реальный запуск возвращает `WinError 2`, а проверенные доступные Windows/runtime-каталоги не содержат движок и `rus/eng.traineddata`. Это ошибка до распознавания, не доказанный timeout или сбой качества OCR. Подробности и границы поиска — `OCR-DISCOVERY-NOTES.md`.

**Решение пользователя: не устанавливать.** Бинарники/языки не скачивались, системный PATH не менялся. Успешное OCR поэтому не заявляется.

Исправлены:

- одинаковое обнаружение executable и tessdata в launcher, worker и health;
- отдельный `Tesseract__TessdataPath`;
- предметные коды `ocr_executable_unavailable`, `ocr_missing_languages`, `ocr_timeout`, `ocr_process_failed`, `ocr_no_text`;
- ограниченные preflight/timeout, завершение дочернего процесса и безопасная обработка stderr;
- поиск существующего runtime в плоском Git worktree, вместо ошибочного пути на два уровня выше.

На реальном PNG worker вернул русскую инструкцию с `[ocr_executable_unavailable]`; admin health показал `ocr.status=Unavailable` и тот же код. Текстовый PDF независимо прошёл обработку до `NeedsReview`. Настройка для будущей установленной копии описана в `README-LOCAL.md`.

### 5. Создание и автоматическое предложение видов

**Вручную:** в карточке администратор выбирает «Создать новый вид» → вводит название/схему → «Создать и выбрать» → «Сохранить назначение». Оператору не предоставлено создание через UI или API. Создание и назначение прочитаны обратно через API и проверены после reload.

**Автоматически:** неизвестный документ с извлечённым текстом передаётся локальной Ollama; новый вид создаётся неактивным черновиком. Подтверждение администратором по-прежнему обязательно. Вид не является новой обученной OCR-схемой: для письма/накладной можно выбрать «Без схемы — хранение и поиск».

Подтверждённые проблемы старого кода:

- валидный ответ `name:null` навсегда помечался успехом и больше не повторялся при том же тексте/модели;
- такой же окончательный успех мог сохраняться без назначения уже существующего неактивного вида;
- ошибки сети уже повторялись, но без отдельного видимого статуса и ручного повтора;
- самостоятельный API по умолчанию имеет `AiReview:Enabled=false`, в отличие от launcher;
- без OCR-текста у изображения автоматическому определению нечего анализировать.

Теперь есть статусы в карточке, повтор администратором, ограничение частоты 30 секунд и долговечная очередь/claim. Ошибка повторяется автоматически не ранее пяти минут, отсутствие предложения — 30 минут; миграция схемы не нужна. Устаревший AI-ответ не должен перетирать новое назначение.

**Реально получено:** на первом PDF локальная модель предложила «Служебное письмо»; подтверждены `isDraft=true`, `isActive=false`, затем реальная активация. Дополнительный прогон с фактически недоступным model endpoint получил `RetryScheduled`, `429` при раннем повторе, сохранил состояние после перезапуска API и после разрешённого повтора создал один черновик через настоящую Ollama. Последующее подтверждение выполнено реальными кнопками браузера и проверено API.

Качество маленькой модели не гарантируется: во втором прогоне она предложила слишком общее название «Управление». Это аргумент сохранять проверку/переименование администратором, а не автоматически активировать результат.

## Проверки и доказательства

Два ограниченных foreground-прогона использовали настоящие API, worker, PostgreSQL, Ollama и headless Chrome; API-моков и поддельных model responses не было. Использованы реальные синтетические документы из существующего evaluation corpus. Unit/integration tests не создавались и не запускались.

- `npm run build` после интеграции успешен. Предупреждение Vite: основной minified chunk немного больше 500 kB; оно не скрыто и не блокирует сборку.
- API и Worker собраны: 0 ошибок, 0 предупреждений.
- Основной прогон: 37 проверочных утверждений, все успешны; `docs/verification/ux-repair/observations.json`.
- Дополнительный прогон повтора/восстановления AI и подтверждающий визуальный проход: `docs/verification/ux-repair/retry-observations.json`.
- Проверены ширины 1440, 1100 и 390 px; переполнения самой страницы в просмотренных users/catalog/upload/document сценариях нет. Горизонтальная прокрутка широких таблиц остаётся внутри таблицы.
- Сохранены desktop/mobile PNG в `docs/verification/ux-repair/`; это реальные страницы временных проверочных баз, не исходные пользовательские скриншоты и не рабочие документы.
- В основном прогоне не было JavaScript pageerror.
- Один Impeccable detect вернул только предупреждение о выбранном Inter. Шрифт закреплён существующим DESIGN.md и сохранён намеренно; это не основание менять тему при функциональном исправлении.
- Собственные процессы завершены, порты проверены закрытыми, обе временные БД и отдельные каталоги оригиналов удалены с подтверждением. Рабочая `documentflow` не использовалась.

## Ограничения

- Доступного Tesseract нет; успешное OCR, нативные missing-language/stderr/timeout и качество распознавания не проверены. Это согласованное ограничение, не выполненная установка.
- File drag проверен браузерными `DataTransfer` с настоящими байтами corpus-файлов; физический жест из Windows Explorer, особенно первоначальное попадание непосредственно во встроенный PDF iframe, отдельно человеком не проверялся. При получении file drag iframe hit-testing отключается, чтобы дальнейшие события оставались у приложения.
- 30-минутное автоматическое истечение `NoProposal`, межпроцессная гонка нескольких API-инстансов, потеря HTTP-ответа при создании вида и загрузка во время смены токена отдельно живым прогоном не проверялись. Временный отказ AI, серверный cooldown, restart и успешное восстановление проверены.
- Это не deployment: приложение после проверки остановлено. Для исправленной версии запускайте `ddd/DocumentFlow-Stitch/Start-DocumentFlow.cmd`; не верхний launcher исходной ветки.
- Независимый финальный обзор выполнен: блокирующих замечаний нет. Подлинность вердикта, исходный HEAD/index/diff и отпечатки 24 файлов приложения перепроверены родительским исполнителем. Подробности области и две отложенные рекомендации — `UX-REPAIR-ACCEPTANCE.md`. Исходный JSON-вердикт сохранён локально вне Git без изменения.
