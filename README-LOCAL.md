# DocumentFlow — историческая инструкция локальной рабочей копии

> Эта запись относится к прежней подготовленной среде. Пути к исходному компьютеру обезличены; указанные ниже наличие программ, состояние OCR и результаты проверок нельзя автоматически переносить на новый компьютер. Для воспроизводимого запуска из публичного репозитория начните с корневого [README.md](README.md), создайте собственные секреты и установите внешние зависимости.

## Как открыть на этом компьютере

1. Откройте `C:/Users/<user>\Desktop\ddd\Start-DocumentFlow.cmd` двойным щелчком. Такой же launcher есть в корне `source`.
2. Дождитесь строки `DocumentFlow: http://localhost:5173`. Браузер откроется автоматически. Первое выполнение собирает API, Worker и интерфейс; нужен интернет для восстановления зависимостей.
3. Пользователь — `admin`. Пароль находится в `C:/Users/<user>\Desktop\ddd\DocumentFlow-runtime\local-secrets.json`, поле `adminPassword`. Не отправляйте этот файл вместе с исходниками и не публикуйте его.
4. Оставьте окно запуска открытым. **Ctrl+C** штатно останавливает только запущенные им процессы. Данные и оригиналы сохраняются между запусками. Закрывать окно крестиком менее безопасно: можно прервать корректное завершение БД.

Командная строка из корня `source`:

```text
python tools/local_stack.py
python tools/local_stack.py --no-build
```

Второй вариант подходит после успешной сборки, пока исходники не менялись. Если `python` отсутствует в PATH, `.cmd` пробует Python из установленного Hermes. Для самостоятельного переноса на другой ПК нужны Python 3, Node.js/npm, .NET SDK 10 и локальное окружение, описанное ниже.

Launcher проверяет занятость портов и **не убивает чужие процессы**. В этом режиме доступны только loopback-адреса:

| Компонент | Адрес |
|---|---|
| Интерфейс | `http://localhost:5173` |
| API | `http://127.0.0.1:5214` |
| PostgreSQL | `127.0.0.1:15439` |
| Ollama | `http://127.0.0.1:11445` |

Это локальный developer launcher, не Windows-служба и не production deployment. Нельзя открывать Vite/dev API в интернет без отдельной настройки HTTPS, reverse proxy, доступа и резервного копирования.

## Что добавлено

- **Поиск** — отдельная вкладка с текстовым и настоящим семантическим режимом, видами, отделами, статусами, архивом и ИНН. Запрос и фильтры сохраняются в URL. Семантика использует локальные `bge-m3` embeddings; при недоступной модели нет скрытой подмены обычным поиском.
- **Справочники** — администратор добавляет/редактирует виды и отделы. Неиспользуемый пользовательский отдел удаляется; используемый деактивируется с сохранением связей. Системные коды защищены, названия можно редактировать.
- **Автоматические виды** — для неизвестного документа локальная AI предлагает новый вид; это не создание нового файла. Вид создаётся как неактивный черновик, выделяется красной рамкой и явным предупреждением. Администратор может исправить и подтвердить предложение. Автоматическое подтверждение реквизитов не выполняется.
- **Кинотеатр** — кнопка в предпросмотре открывает рабочую область на весь viewport. Оригинал и форма/AI рядом, раздельная прокрутка; выход по кнопке и Escape с возвратом фокуса. На узком экране — последовательное расположение.
- **Сохранность** — серверные черновики пользователя, восстановление после перезагрузки, предупреждение ухода, ограниченная аварийная копия в sessionStorage текущей вкладки (30 минут; не постоянный localStorage). Версия документа защищает подтверждение от перезаписи чужих изменений. У серверного черновика есть отдельная проверка ревизии: устаревшая вкладка получает 409, не стирая сохранённый вариант. Аварийные копии конфликтующих версий сохраняются отдельно в пределах исходных 30 минут.
- **Исправление завершённого документа** — возврат на проверку с причиной и сохранением предыдущего результата в истории. Неподдерживаемый документ можно убрать из активной очереди с отдельным решением, не выдавая его за подтверждённый.
- **Реестр и результат** — номер, дата, ИНН, сумма; выгрузка CSV подтверждённых реквизитов с UTF-8 BOM, защитой формул и ограничением 10 000 строк. Фильтр статуса «Требует проверки» даёт пустой CSV: неподтверждённые значения намеренно не экспортируются как готовые.
- **Проверка очереди** — «Подтвердить и следующий» и «Пропустить», возврат к исходному URL выборки. Очередь не является системой поручений с владельцем/блокировкой документа.
- **Загрузка и сеанс** — добавление/замена выбранных файлов, лимит партии 100 МиБ, предупреждение ухода, история ссылок текущей вкладки без содержимого файлов; объяснение повторного входа после смены пароля.

Пользовательский вид и техническая схема различаются. Схемы извлечения обязательных реквизитов пока только «Счёт», «Договор», «Акт». Для остальных видов есть «Без схемы — хранение и поиск». Назначение нового вида само по себе не обучает распознаватель, не генерирует новую схему реквизитов и не завершает ручную проверку.

## Данные и модели

По умолчанию runtime ищется в `ddd/DocumentFlow-runtime`; можно переопределить переменной `DOCUMENTFLOW_RUNTIME`.

```text
DocumentFlow-runtime/
  pgsql/bin/                   portable PostgreSQL 17
  pgdata/                      существующий кластер PostgreSQL
  ollama/ollama.exe             локальный сервер моделей
  models/                      модели Ollama
  local-secrets.json            локальные пароли и JWT key, вне Git
  documents/documentflow/      оригиналы рабочей базы
  api.log, worker.log, ...      локальные журналы
```

На этом ПК portable PostgreSQL и Ollama загружены отдельно от исходников; модели `bge-m3` и `qwen2.5:0.5b-instruct` уже скачаны. Launcher не удаляет базы. Проверочные прогоны создавали отдельные базы `documentflow_verify_*`, они не смешиваются с рабочей `documentflow`.

Модель 0.5B выбрана для ограниченных ресурсов локальной демонстрации. Её подсказки могут быть плохими или содержать выдуманные значения — всегда сверяйте оригинал. Для реальной работы можно настроить более качественную бесплатную локальную модель с предварительной проверкой её собственной лицензии и требований к RAM/VRAM.

Для переноса окружения: установите/распакуйте PostgreSQL и Ollama в указанные каталоги; создайте секреты случайным генератором, инициализируйте кластер `initdb` с пользователем `documentflow` и `--auth=scram-sha-256`; пароль БД должен совпадать с `databasePassword`. `local-secrets.json` должен содержать `databasePassword`, `adminPassword` (не менее 12 символов, разные регистры, цифра, спецсимвол), `jwtKey` (не менее 32 случайных байтов). Подключите Ollama к `models`, выполните загрузку обеих моделей. Не копируйте `pgdata` работающего сервера — используйте `pg_dump`/`pg_restore` либо корректную холодную копию.

OCR изображений/сканированных PDF требует отдельно установленного **Tesseract** с языками `rus+eng`. Доступный движок на этом ПК не найден; реальный worker возвращает `[ocr_executable_unavailable]`, health — `Unavailable`. По решению пользователя установка не выполнялась. DOCX и текстовые PDF, справочники и AI по уже извлечённому тексту работают независимо от OCR.

Если движок будет установлен позже, можно распаковать его в `DocumentFlow-runtime/tesseract/` вместе с `tessdata/rus.traineddata` и `tessdata/eng.traineddata`: launcher проверяет этот путь, а также стандартные Windows-каталоги. Системный PATH менять не нужно. Для нестандартного пути задайте перед запуском в обычном Windows CMD (подставьте существующие пути):

```bat
set "Tesseract__ExecutablePath=C:\path\to\tesseract.exe"
set "Tesseract__TessdataPath=C:\path\to\tessdata"
set "Tesseract__Languages=rus+eng"
Start-DocumentFlow.cmd
```

Проверка установленного движка: `"C:\path\to\tesseract.exe" --tessdata-dir "C:\path\to\tessdata" --list-langs`. В списке должны быть `rus` и `eng`. После исправления окружения перезапустите launcher и нажмите «Повторить обработку» в карточке ошибочного документа. Установка вида документа не заменяет распознавание изображения.

### Уточнения UX и видов

- Единая кнопка **«Загрузить документы»** принимает один или несколько файлов; отдельного пакетного режима нет. При file drag над авторизованным интерфейсом включается полноэкранный приём. Drop добавляет файлы в список, а не отправляет их автоматически. Если отменить уход с несохранённой формы, перетащенные файлы остаются в памяти вкладки с действием «Открыть список».
- В карточке администратору доступно **«Создать новый вид» → «Создать и выбрать» → «Сохранить назначение»**. Для неизвестного документа обычно нужна схема «Без схемы — хранение и поиск». Операторы создают запрос через администратора, права API не расширялись.
- У неизвестного документа показан статус автоматического определения. Ошибка AI повторяется автоматически не ранее чем через 5 минут, отсутствие предложения — не ранее 30 минут. Администратор может запросить повтор отдельно, с 30-секундным ограничением частоты. AI-предложения остаются неактивными черновиками до подтверждения.
- Для этой версии запускайте **`ddd/DocumentFlow-Stitch/Start-DocumentFlow.cmd`**. Верхний `ddd/Start-DocumentFlow.cmd` по-прежнему открывает исходную ветку; переключение не выполнялось.
- Фактическая приёмка, причины и ограничения: `docs/UX-REPAIR-REPORT.md`; исходный план — `.hermes/plans/documentflow-ux-repair.md`.

## Миграции и обычное развёртывание

Добавлена EF-миграция `WorkspaceReviewAndSemanticSearch`. Она добавляет независимую GUID-версию старым документам, таблицы справочников, назначений, смыслового индекса, AI-discovery, черновиков, предыдущих результатов и решений. Не удаляет старые документы. Перед применением к чужой рабочей БД обязательно сделайте резервную копию.

В локальном launcher задано `Database__ApplyMigrations=true`. В production эта опция **не включена по умолчанию**: миграции применяет оператор EF-инструментом. После миграции API идемпотентно создаёт системные виды/отделы и недостающие назначения. Worker не запускает отдельный индексатор — он работает в API.

Новые параметры: `SemanticSearch__Enabled`, `SemanticSearch__BaseUrl`, `SemanticSearch__Model`, `SemanticSearch__BatchSize`, `SemanticSearch__IntervalSeconds`, `SemanticSearch__TimeoutSeconds`, `AiReview__Enabled`, `Ollama__BaseUrl`, `Ollama__Model`, `Ollama__TimeoutSeconds`.

## Лицензии и границы

«Бесплатно» не означает «без лицензии»: стороннее открытое ПО имеет условия сохранения авторства и уведомлений. Обязательные платные AI API, ключи или подписки не добавлены. Сведения по пакетам и ограничениям native-компонентов — в `docs/THIRD_PARTY_NOTICES.md`; историческая полная инвентаризация — `docs/dependency-licenses.json`, актуальный frontend после исправления npm-уязвимостей — `docs/frontend-dependency-licenses-current.json`. Не трактуйте эти документы как юридическую гарантию или разрешение не прикладывать чужие NOTICE.

Оригинальный архив handoff не менялся. Доработки находятся в `source` и фиксируются локальным Git. Новые unit/integration tests не добавлялись и старые не запускались; проверка — реальные сборки, HTTP, модели и браузер. Исходные тестовые проекты/файлы и их прямые dev-зависимости удалены; оригинальный handoff остаётся нетронутым. Полный solution собирается без тестовых проектов.
