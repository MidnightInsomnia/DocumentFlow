# DocumentFlow — план реализации доработок

**Цель:** закончить текущие рабочие сценарии и добавить отдельный поиск, управляемые справочники видов/отделов и режим кинотеатра без платных сервисов и зависимостей с коммерческими ограничениями.

**Разрешение:** пользователь поручил исправить всё необходимое и самостоятельно принимать оставшиеся решения. Для автоматического вида выбран вариант A: AI создаёт черновик вида, вид выделяется красной рамкой и подтверждается администратором. Исходный ZIP не менять.

**Стек:** существующие .NET 10 / EF Core / PostgreSQL / React. Семантика через локальный Ollama / bge-m3 (MIT). Не выдавать лексический поиск за семантический при недоступной модели. Существующие enum Invoice/Contract/Act сохранить как технические схемы распознавания, а пользовательские виды/отделы хранить в редактируемых справочниках. Новые виды не менять автоматически на активные.

**Проверки:** новые тесты не писать, существующие не запускать; в окончательной поставке удалить тестовые проекты/файлы и их прямые зависимости согласно принятому правилу работы. Сборки, реальные HTTP-сценарии, браузерные клики и скриншоты. Не использовать фоновую Hermes-задачу для проверок: запуск, пробы и остановка в одном foreground-вызове. Независимое ревью — один раз в конце. Коммиты на русском. Git в поставке отсутствует; создать локальный репозиторий с исходным состоянием до реализации.

## 1. Основа и лицензии

- Сохранить оригинальные файлы baseline-коммитом; исходный ZIP остаётся резервной копией.
- Проверить лицензии прямых и транзитивных зависимостей и выбранных моделей по метаданным пакетов/официальным источникам. Создать THIRD_PARTY_NOTICES.md и машиночитаемый перечень.
- Удалить SixLabors.ImageSharp с ограничительной Split License из рабочего приложения; заменить TIFF/OCR rasterization на бесплатную permissive-библиотеку с сохранением лимитов страниц/пикселей/памяти. Не обещать «без лицензий»: соблюдаются уведомления свободных лицензий.
- Сохранить существующую предметную структуру UI (Operate), без визуальной перерисовки.

## 2. Контракт расширения данных

Создать таблицы и EF migration:
- DocumentKinds: Id, Name, NormalizedName, BaseType (существующая техническая схема), IsActive, IsDraft, IsSystem, CreatedAutomatically, CreatedAtUtc.
- OrganizationDepartments: Id, Name, IsActive, IsSystem, CreatedAtUtc.
- DocumentWorkspace: DocumentId, KindId?, DepartmentId?, Resolution?, ResolutionReason?, LastUpdatedAtUtc. Каталоги не удалять каскадно вместе с документами.
- DocumentSearchIndex: DocumentId, Model, SourceFingerprint, Embedding JSON, IndexedAtUtc; не требовать внешнего vector DB.
- Для безопасной ручной работы: версия документа/результата, серверный черновик пользователя и история значений. При необходимости применить отдельные сущности без поломки legacy данных.

API справочников/поиска:
- GET /api/catalogs — active kinds/departments для всех авторизованных; admin дополнительно видит drafts/inactive.
- GET/POST /api/admin/catalogs/kinds, PUT/DELETE /api/admin/catalogs/kinds/{id}; POST /{id}/approve. Создание/редактирование принимает name, baseType, departmentId?; системные коды стабильны.
- GET/POST /api/admin/catalogs/departments, PUT/DELETE /api/admin/catalogs/departments/{id}. При использовании — безопасная деактивация либо 409, а не потеря истории.
- GET /api/workspace/documents/{id}; PUT с kindId?, departmentId? — назначение активных справочников; права проверяются сервером.
- GET /api/search/documents?q=&mode=text|semantic&type=&status=&departmentId=&kindId=&inn=&archive=active|archived|all&page=1&pageSize=20 — paged items, semanticAvailable, indexedCount, message; возвращает id/fileName/status/type/targetDepartment/timestamps/isArchived и номер/дату/ИНН/сумму/kindName/departmentName/score?/snippet.
- GET /api/search/counterparties?q= — ИНН, количество, последние документы; не называть агрегат задолженностью.
- POST /api/admin/search/reindex — bounded реальная индексация; GET /api/admin/search/status.

Индексирование, автоматические черновики видов: hosted service с bounded batch, отменой, исключениями на конкретный документ и отсутствием зависимости основной обработки от AI. AI-ответ проверяется и ограничивается, dedupe по нормализованному имени, документы/промпты не пишутся в логи. Неподдерживаемые типы не подтверждаются автоматически.

## 3. Сохранность и корректировка

- Версия результата и optimistic concurrency. Review request содержит expectedVersion; существующие клиенты могут иметь ограниченную совместимость, новый UI всегда передаёт версию.
- PUT/GET /api/documents/{id}/review/draft — серверный черновик текущего пользователя. Не класть чувствительные поля в постоянный localStorage. Восстановление черновика, guard ухода, явные состояния сохранения, корректная работа при 401.
- POST /api/documents/{id}/reopen — причина, перевод Completed обратно на проверку, история предыдущих реквизитов/автора, защита от processing/archived.
- POST /api/documents/{id}/resolve — notSupported/irrelevant с причиной; отдельное предметное решение и исключение из активной очереди без подмены типа.
- POST review должен быть атомарен относительно версии/статуса; fields заблокированы при отправке.
- Исправить races списка и карточки (AbortController / request epoch; loading снимается успешным актуальным ответом).

## 4. Правдивость результата и ввод

- Diagnostics различают checked, insufficientData, notApplicable, error; reason отображается в UI.
- Связи по номеру — кандидаты, не доказанная связь; пользователь видит основания и ограничения.
- Не называть фиксированный rule-score вероятностью правильности; изменить пояснение уверенности.
- Нормализовать суммы с запятой/пробелами; required/aria-required/inputMode/ограничения. Ошибки у конкретного поля, исправленные подсказки не остаются якобы актуальными.
- Раздельные error/loading для preview/download, retry, понятные ошибки сети и session; не скрывать последний успешный экран при временном poll-сбое.
- Export CSV подтверждённых реквизитов с защитой formula injection, UTF-8 BOM, согласованными фильтрами.

## 5. Пользовательские экраны

Наследовать существующие цвета, типографику и элементы. Новые библиотеки UI не требуются.
- Отдельная вкладка «Поиск»: режим по смыслу/по тексту, фильтры, поиск по контрагенту, URL-state, понятные empty/loading/error, результат с реквизитами и основанием совпадения. Для semantic нет скрытой подмены text-search.
- Админка «Справочники»: виды и отделы, создание/редактирование/деактивация, подтверждение AI-черновика. Автоматический новый вид выделен красной рамкой + текстом «Автоматически предложен — требует подтверждения», не только цветом.
- Кинотеатр: toggle в preview, viewport-wide рабочее пространство, оригинал слева и форма/AI справа, раздельная прокрутка, доступный выход/Escape, возврат фокуса; на mobile последовательный режим без overflow. AI находится рядом с оригиналом, не внизу длинной карточки.
- Сохранение URL фильтров при карточке/возврате; «Подтвердить и следующий» и «Пропустить».
- Реестр: деловые реквизиты, коррекция пустой страницы, свернутые дополнительные фильтры, локальная проверка дат, последнее обновление.
- Загрузка: предупреждение ухода, ids партии в sessionStorage без содержимого файлов, добавить/заменить, общий лимит 100 МиБ, адаптивность промежуточных ширин.
- Пояснения ролей/паролей, перенос успеха смены пароля на login.

## Критерий завершения

Каждый из четырёх пунктов пользователя реализован end-to-end либо явно отмечен конкретный блокер; никакой scaffold не выдаётся за работающую функцию. Исправления аудита проверены в пределах описанной фактической среды. Семантический поиск не является замаскированным keyword-поиском. Новые виды AI — только drafts до решения администратора. Платные ключи/подписки не нужны.

## Единственный post-review fix-pass

Исходное заключение `docs/verification/final-code-review.json` сохранено неизменным, passed=false. Его SHA-256, HEAD/index/tree и все 301 исходный fingerprint проверены родителем до исправлений. Шесть находок перепроверены по реализации; все подтверждены. Дополнительных ревью не запускать.

1. DF-L01: хранить конфликтующие аварийные копии отдельно по версии, не стирать их при открытии чистой новой версии; сохранять исходный TTL и возможность копирования после повторной перезагрузки/нового редактирования.
2. DF-L02: CAS самого серверного черновика через ожидаемый UpdatedAtUtc, отдельно от версии документа; отправлять известный token из UI, выдавать 409 устаревшей вкладке. Использовать точность PostgreSQL microseconds и монотонное время внутри lock.
3. DF-L03: помнить просмотренные ID текущего прохода очереди и искать непросмотренные с учётом пагинации; пропуск не должен возвращать A/B/A/B или объявлять skipped-документы завершёнными.
4. DF-L04: background/startup/fallback создают новые назначения только активных подтверждённых видов и активных отделов; прежние связи сохраняются.
5. DF-L05: фоновое чтение назначения обновляет серверный снимок, но не dirty controls; успешное явное сохранение снимает защиту.
6. DF-L06: единое представление пустого значения черновика — строка; backend нормализует null, frontend читает и старые nullable данные без потери остальных полей.

Проверка: полный build solution/frontend, реальные конкурентные сохранения черновиков, null roundtrip + browser recovery, два reload после смены версии и редактирование новой версии, три последовательных пропуска и пагинация, деактивация системного каталога до обработки и startup-backfill, ожидание настоящего 15-секундного обновления при ручном выборе. Один foreground-вызов запускает/проверяет/останавливает окружение. После этого родительская квитанция закрытия с hash исходного ревью и перечнем реально проверенных исправлений, актуализация документации и русский коммит. Suggestions DF-S01/DF-S02 не включать в scope этого исправления.
