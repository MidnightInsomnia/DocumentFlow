## Предварительная оценка по двум скриншотам

- Сильная сторона: оригинал рядом с извлечёнными данными и назначением; навигация предметная, основные поля подписаны.
- Проблемы UX: независимая прокрутка правой панели может перехватывать колесо даже без переполнения; роль одновременно представлена badge, подписью и select; создание нового вида недоступно непосредственно из назначения документа.
- Визуальные проблемы: дублирование элементов утяжеляет таблицу, длинные подписи не получают устойчивого внутреннего отступа, правая панель оставляет избыточную пустоту. Исправлять композицию и контракты общих компонентов, а не добавлять декоративные карточки.
- Пакетный приём полезен; отдельная кнопка с техническим названием не нужна, если одна общая загрузка принимает один или несколько файлов и сохраняет пофайловые результаты.

## Один исполнительный этап: законченный корректирующий выпуск

Работа выполняется последовательно по разделам ниже. Самостоятельный read-only аудит не считается завершением этапа.

### 1. Подтвердить причины и зафиксировать оценку

- Прочитать текущие компоненты карточки, preview/cinema, пользователей, загрузки, Layout, справочников и назначения; проверить связанные API и сервисы OCR/AI-discovery.
- Уточнить каскад CSS, размеры scroll-контейнеров и обработчики drag/drop.
- Проверить установленный Tesseract, обнаружение executable, языковые данные, окружение worker, обработку exit code/timeout и сообщения health.
- Проследить цепочку неизвестный документ → OCR/текст → индексатор → AI → предложение вида → подтверждение → назначение.
- Описать причины по фактам; не объявлять отсутствие runtime-проверки доказанным исправлением.

### 2. Исправить карточку и общие визуальные дефекты

- В обычной карточке прокрутка над правой областью должна перемещать содержимое/страницу, а не попадать в тупик. В cinema обе рабочие области остаются доступными и корректно прокручиваются.
- Убрать лишнее повторение роли: в каждой строке пользователей один select с доступным названием; сохранить подтверждение понижения и серверные ограничения.
- Исправить внутренние отступы и сжатие текста в пункте администрирования, статусах видов, кнопках и select. Не скрывать проблему ellipsis там, где важна полная подпись.
- Сохранить четкие группировки и компактную иерархию без полной смены темы.

### 3. Объединить загрузку и сделать глобальный drag & drop

- Единое понятное действие «Загрузить документы» для одного и нескольких файлов; пакетная обработка и пофайловые результаты сохраняются.
- При перетаскивании файлов над авторизованным приложением показывать полноэкранную область приёма.
- Отслеживать только файлы, не ссылки/выделенный текст; не открывать файл браузером по умолчанию; убрать мерцание при переходе между дочерними элементами.
- Доставка файлов в общую страницу загрузки без потери выбранных файлов; существующие ограничения размера, типов, повторов и защита несохранённых изменений остаются.
- Проверить drop поверх документа, навигации, правой панели и уже открытой страницы загрузки, а также отмену drag.

### 4. Устранить подтвержденную причину сбоя OCR

- Исправить обнаружение/конфигурацию Tesseract и окружение локального launcher либо обработку его ошибок — в зависимости от воспроизведённой причины.
- Не имитировать успешный OCR и не заменять распознавание пустым текстом. Проверить реальный executable и `rus+eng`, затем реальный образец через worker.
- Сделать сообщения ошибки пригодными для действий: недоступен executable, отсутствует язык, превышено время или ошибка обработки различаются.
- Не скачивать неофициальные бинарники и не менять системный PATH без необходимости. Если потребуется установка, выбрать безопасный локальный путь и явно документировать зависимость.

### 5. Исправить создание и предложение новых видов

- Дать администратору явный путь «Создать вид» непосредственно из карточки неизвестного документа с последующим назначением.
- Не обходить права оператора; сохранить ручное подтверждение автоматических AI-предложений.
- Сделать состояние автоматического определения понятным: ожидание, недоступность AI/OCR, предложение, ошибка, повтор при необходимости. Нельзя навечно помечать попытку выполненной после временного сбоя.
- Учитывать новые/неактивные виды в UI корректно; ясно различать пользовательский вид и схему извлечения (новый вид не означает автоматическое обучение OCR).
- Проверить реальный неизвестный документ, создание/активацию/назначение и повторный запрос после временного сбоя.

### 6. Сборка и конечная проверка

- Выполнить production-сборку frontend и сборки API/worker после интеграции всех правок.
- Поднять реальный стек с отдельной проверочной БД и отдельным хранилищем, не использовать API-моки и не писать в рабочие документы.
- Реальными браузерными действиями проверить: скролл справа, cinema/выход, один role-select, подтверждения, длинные подписи, единую загрузку, полноэкранный drop, новый вид и сообщения OCR.
- Одним пакетным визуальным проходом проверить desktop/intermediate/mobile; исправить обнаруженные дефекты одним набором, максимум один подтверждающий проход.
- Один раз запустить Impeccable detect на изменённых UI-файлах; функциональные результаты важнее стилистических предупреждений, заданная тема сохраняется.
- Один независимый финальный обзор совокупного diff, без параллельных повторных ревью. Подтверждённые блокеры исправить и проверить адресно.
- Проверить cleanup только собственных временных процессов/ресурсов; не удалять рабочие файлы и чужие БД.

## Критерии готовности

1. Колесо над правой панелью не блокируется; элементы внизу доступны в обычном и cinema-режиме.
2. В строке пользователя ровно один элемент управления ролью без повторного badge/подписи.
3. Длинные надписи администрирования и статусов имеют видимый внутренний отступ, не обрезаются.
4. Для загрузки не требуется выбирать отдельный пакетный режим; глобальный drop принимает файлы в общую очередь.
5. Причина сбоя Tesseract подтверждена реальной диагностикой; исправленный OCR проверен на настоящем файле либо незакрытый внешний блокер назван прямо.
6. Новый вид можно создать и назначить из карточки; автоматические предложения не пропадают молча и остаются требующими подтверждения администратора.
7. Сборки успешны, выполнены реальные доступные сценарии, ограничения не скрыты; изменения закоммичены.
